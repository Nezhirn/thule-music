# Thule Music — план работ

Порядок: сначала доводим бэкенд, потом пишем web-клиент, потом KMP-приложения (Android, Linux). Архитектура — в [architecture.md](architecture.md).

Каждый пункт сдаётся отдельным коммитом с тестами.

## Фаза 1.5 — доводка бэкенда

**Данные пользователя и контракт**
- [x] Перенос/переименование файлов не теряет трек: скан сопоставляет исчезнувшие и новые пути (размер + mtime + длительность) и меняет путь, а не удаляет трек. Иначе пропадают лайки, плейлисты, история, а альбом снова всплывает в New Releases.
- [x] `stream-url` отдаёт относительный путь. Абсолютный строился из `Host` и ломался за nginx и за HTTPS в docker.
- [x] Коды ошибок: каждый ответ с ошибкой содержит стабильный `code` — клиенты переводят сообщения (RU/EN).
- [x] Понятные `operationId` в OpenAPI (`list_artists`, а не `list_artists_api_v1_artists_get`).

**Нужно интерфейсу**
- [x] `GET /auth/setup` — нужен ли первый запуск (создание админа).
- [x] Настройки пользователя на сервере (`/me/preferences`): язык, акцентный цвет, блюр вкл/выкл, подстройка под обложку, качество потока.
- [x] Профиль: смена имени и пароля (смена пароля закрывает остальные сессии), аватар — по умолчанию нет, можно загрузить фото; админ сбрасывает пароль пользователю.
- [x] Избранные альбомы и артисты (кнопка Save, раздел в библиотеке).
- [x] Палитра обложки вместо одного среднего цвета: основной, яркий, приглушённый, яркость; пересчёт для уже загруженных обложек.
- [x] Сводка задач для админки (прогресс скана).

**Надёжность и безопасность**
- [x] Замена обложки (встроенной или `cover.jpg`) подхватывается при пересканировании.
- [x] Скан ставит задачи импорта одной пачкой, а не по запросу на файл.
- [x] Таймаут для ffmpeg.
- [x] Периодическая уборка: старые задачи, просроченные refresh-токены, файлы перекодировок и обложек удалённых треков.
- [x] Ограничение попыток входа: 10 неудачных за 15 минут на имя пользователя, дальше 429 с `Retry-After`.

**Найдено на тестовой подборке** (реальные случаи тегов, см. [architecture.md](architecture.md#конвейер-импорта))
- [x] cp1251 под видом Latin-1 и не-UTF-8 во FLAC читаются как кириллица.
- [x] «feat.» и несколько исполнителей: приглашённые — отдельные артисты, а не «A feat. B»; у артиста — раздел «участвует в».
- [x] Мусор в полях не роняет импорт: длинные названия обрезаются, кривые год, номер и жанр отбрасываются.
- [x] Обложка в папке альбома над CD1/CD2.
- [x] Для каталога: жанры (`GET /genres`), сортировка альбомов по артисту, треков — по названию, артисту, альбому; на главной «Недавно добавленные» отдельно от «Новых релизов» (по году).

**Позже, вместе с Android:** синхронизация очереди между устройствами.

## Фаза 2 — web-клиент

Стек: Vite + React + TypeScript, TanStack Query, `openapi-typescript` + `openapi-fetch`, React Router, Zustand (плеер), CSS Modules + CSS-переменные. Пакетный менеджер — npm. Интерфейс на русском и английском.

| Этап | Содержание |
|---|---|
| ✅ 0. Каркас и стенд | `web/`, генерация типов из OpenAPI и проверка их актуальности, E2E-стенд, `npm run verify` |
| ✅ 1. Вход | первый запуск, вход, обновление токена, выход, RU/EN (перенесено из этапа 2: экраны входа — первые экраны с текстом) |
| ✅ 2. Оболочка | раскладка, дизайн-система, настройки: внешний вид, язык, качество потока, профиль (имя, фото, пароль) |
| ✅ 3. Каталог | главная, альбомы, артисты, треки |
| ✅ 4. Плеер | очередь, перемотка, shuffle/repeat, качество, Media Session, скробблинг |
| ✅ 5. Моё | лайки, избранное, плейлисты, история |
| ✅ 6. Поиск и тексты | поиск по мере ввода, тексты песен (статичные, без подсветки строк) |
| ✅ 7. Админка | скан и задачи, загрузка файлов и папок альбомов, пользователи |
| 8. Продакшн | FastAPI раздаёт `web/dist`, общий Dockerfile |

**Токены.** Refresh-токен хранится в localStorage. Бэкенд считает повторное использование refresh-токена кражей и закрывает все сессии, поэтому обновление идёт строго по одному: внутри вкладки — общий промис, между вкладками — Web Locks API, перед обновлением токен перечитывается из хранилища. Web Locks есть только на HTTPS и localhost; если сервер открыт по HTTP, вкладки могут столкнуться. Тогда вторая получает `refresh_token_rotated` (30 секунд после обмена это не считается кражей), дожидается нового токена от первой вкладки и повторяет запрос.

**Язык.** Интерфейс показывается на последнем языке, выбранном на этом устройстве, а до первого выбора — на языке браузера. При входе язык из настроек аккаунта, если он там задан, применяется и запоминается на устройстве. Переключатель в аккаунте сохраняет выбор на сервер, так что язык переезжает на другие устройства. Ошибки API переводятся по `code`; набор переводов проверяется типами: новый код ошибки на бэкенде без перевода не соберётся.

**Раскладка.** Шире 1280 px — навигация и плейлисты слева, страница в центре, «Сейчас играет» и очередь справа, плеер внизу. От 900 до 1280 px правой колонки нет: кнопка «Очередь» в плеере открывает её поверх страницы. Уже 900 px — телефонная раскладка: страница на весь экран, разделы во вкладках снизу, медиатека отдельной страницей, мини-плеер над вкладками. Администрированию место внизу боковой панели и в меню аккаунта (на телефоне — только там); видят его только администраторы.

**Тема.** Тёмная. Из акцентного цвета пользователя считаются заливка кнопок, цвет текста на ней (белый или тёмный — какой контрастнее) и оттенок для текста и иконок на стекле. Фон — три мягких цветовых пятна: оттенки акцента, а при включённой подстройке — цвета обложки (`cover_palette`), приглушённые по яркости и насыщенности. Пятна плавно перетекают при смене обложки. Ограничение яркости фона — то, что держит контраст: `web/src/theme/theme.ts` считает самое светлое место, куда может попасть текст (стекло над тремя наложенными пятнами максимальной яркости плюс подсветка строки), и все цвета текста, включая выведенные из любого акцента, проверяются на ≥ 4.5:1 против него — тестом на сотнях случайных цветов. Без блюра панели непрозрачные. В настройках акцент и цвета обложки можно примерить до сохранения: свой цвет — пока открыт системный диалог, обложку — на альбомах из библиотеки.

**Настройки** хранятся на сервере и применяются сразу, до ответа. Если сервер отказал, возвращается только то, что меняло это действие, и только если пользователь не успел изменить это снова; ответ на более раннее изменение не перебивает более позднее. Когда пользователь возвращается во вкладку, настройки и профиль перечитываются: изменения с другого устройства, включая язык, подтягиваются сами.

**Каталог.** На главной: карусель недавно добавленных альбомов, полки «Для вас», «Недавно слушали» (если что-то слушали) и «Новые релизы» (по году), ярлыки самых крупных жанров. Альбомы — сетка с сортировкой (недавно добавленные, по названию, году, артисту) и фильтром по жанру; оба в адресе, поэтому «назад» со страницы альбома возвращает тот же список. Длинные списки подгружаются страницами по 60 по мере прокрутки, а для клавиатуры и экранных читалок есть кнопка «Показать ещё». На странице альбома треки разбиты по дискам. Если на треке есть кто-то кроме исполнителя альбома, все исполнители трека показаны ссылками; у сборника — исполнитель каждого трека. Ниже — другие альбомы того же исполнителя. На странице артиста: популярные треки (5, по кнопке 10), альбомы и «Участвует в». Верх панели на страницах альбома и артиста подкрашен цветом обложки и перетекает при переходе. Сила подкраски ограничена тем же расчётом, что держит контраст текста.

**Плеер.** Играть можно альбом и популярные треки артиста — кнопками «Играть» и «Перемешать» в шапке, альбом — ещё и кнопкой на обложке в сетке. Трек — кнопкой в строке (на месте номера), двойным щелчком по строке или касанием на телефоне: очередью становится весь список. В меню строки — «Играть следующим», «Добавить в очередь», переход к альбому и артисту. Играющий трек подсвечен в таблицах, кнопка «Играть» его альбома становится «Паузой». Внизу — трек, перемешивание, предыдущий/следующий, повтор (выключен, вся очередь, один трек), перемотка, громкость. «Предыдущий» после трёх секунд трека начинает его заново. Когда очередь доиграла, плеер встаёт на её начало. Справа — обложка, качество потока («Opus · 160 кбит/с», «FLAC · 900 кбит/с») и «Далее»: трек из очереди играет по щелчку, его можно убрать, очередь — очистить. На телефоне — мини-плеер над вкладками и полноэкранный плеер с очередью. Пробел ставит на паузу, если фокус не на кнопке или поле. Фон и стекло подстраиваются под обложку играющего трека, если подстройка включена. Как устроены поток, скроббл и сохранение очереди — в [architecture.md](architecture.md#web-плеер). Перетаскивания треков в очереди пока нет.

**Моё.** Сердечко у трека — в строке таблицы (на телефоне — в меню трека), в плеере внизу и в полноэкранном плеере — кладёт его в «Любимые треки». Звёздочка на странице альбома или артиста кладёт их в «Избранное»: там альбомы и артисты, переключатель — в адресе. «Любимые треки» — список с кнопками «Играть» и «Перемешать», которые играют все любимые треки, а не только загруженные. Плейлист создаётся кнопкой «+» у списка плейлистов (на телефоне — в «Медиатеке») или прямо из «Добавить в плейлист». Этот пункт есть в меню трека и в меню альбома (весь альбом). На странице плейлиста — обложка из обложек первых альбомов, описание, «Играть», «Перемешать», меню с «Изменить» и «Удалить». Треки переставляются перетаскиванием или пунктами «Переместить выше» и «Переместить ниже» в меню строки, оттуда же убираются. «История» — все прослушивания по дням («Сегодня», «Вчера», дата), её можно очистить. Лайки и изменения плейлистов видны сразу, до ответа сервера. Если сервер отказал, возвращается прежнее и появляется сообщение. Как это устроено — в [architecture.md](architecture.md#моё-в-web).

**Поиск** идёт по мере ввода: запрос уходит, когда пользователь на четверть секунды перестал печатать, или сразу по Enter. Опечатки прощаются: «сиверный» находит «Северный Ветер». Альбомы и треки находятся и по имени артиста. Сверху — лучшее совпадение с кнопкой «Играть»: артист, альбом или трек, чьё название ближе всего к запросу (при равенстве — артист, потом альбом). Рядом — первые треки, ниже — артисты, альбомы и подходящие плейлисты. Переключатель «Всё / Треки / Альбомы / Артисты» показывает все результаты одного вида, они подгружаются при прокрутке. Запрос и вид результатов — в адресе, поэтому «назад» со страницы альбома возвращает те же результаты. Пока ничего не введено, показаны жанры. «/» или Ctrl+K (⌘K) переводят в поле поиска с любой страницы. Экранные читалки слышат, сколько найдено.

**Тексты песен** показываются статично, по куплетам, без подсветки строк: у текстов с таймкодами таймкоды не показываются. Кнопка «Текст песни» в плеере открывает текст играющего трека на месте страницы, текст сменяется вместе с треком, повторное нажатие возвращает на прежнюю страницу. На телефоне такая же кнопка в полноэкранном плеере показывает текст вместо обложки. Под текстом сказано, откуда он: из файла рядом с треком, из тегов или из LRCLIB. Если у трека нет текста, это объясняется. Файл `.lrc` или `.txt`, положенный рядом с уже отсканированным треком, изменённый или удалённый, подхватывается следующим сканированием.

**Администрирование** — три вкладки, у каждой свой адрес. «Медиатека»: сколько в ней треков, альбомов, артистов, часов музыки и места на диске; сканирование с прогрессом («Добавляем файлы: 19 из 44») и итогом последнего скана (добавлено, обновлено, перенесено, удалено); фоновые задачи — что сейчас в работе (перекодирование, поиск текстов…) и ошибки: какой файл или трек, почему, когда; их можно повторить по одной или все, или очистить. Если скан долго ждёт, страница подсказывает проверить, что на сервере запущен обработчик задач. «Загрузка»: файлы или целые папки альбомов — перетаскиванием или кнопками; вместе с треками загружаются обложка папки и тексты песен рядом с треками. Каждый файл виден до конца: загрузка с процентами, добавление в медиатеку, «Добавлен» со ссылкой на альбом, «Уже есть в медиатеке» (такой же файл не сохраняется второй раз), «Не удалось добавить» с причиной; оборвавшуюся загрузку можно повторить. Загрузка продолжается, пока администратор ходит по приложению, а в конце говорит, сколько добавлено. «Пользователи»: имя, роль, с какого дня, последняя активность, сколько активных сеансов; новый пользователь (с ролью), смена роли, новый пароль, завершение всех сеансов, удаление — с подтверждением. С собой этого не сделать: свои имя и пароль — в настройках.

## Дизайн

Референс — макет в стиле macOS; берём концепцию, а не окно:
- десктоп: навигация и плейлисты слева, контент в центре, Now Playing с очередью Up Next справа, плеер внизу;
- главная: карусель новых альбомов, For You (альбомы по вкусу), New Releases;
- без кнопок окна macOS и без колокольчика уведомлений; мобильная раскладка своя (нижняя навигация, полноэкранный плеер);
- обязательно: блюр с выключателем, выбор акцентного цвета, подстройка блюра и фона под обложку текущего трека;
- контраст текста на стекле — WCAG AA.

## Тестирование

- Бэкенд: `cd backend && .venv/bin/pytest -q`, плюс `ruff check .` и `mypy app`.
- Web: Vitest + Testing Library + MSW для логики и компонентов. `cd web && npm run check` — быстрые проверки, `npm run verify` — вместе с E2E.
- Доступность: E2E прогоняет axe-core (WCAG 2.2 AA и best practices) по экранам входа, главной, настроек, медиатеки, альбомов, артистов, треков, страницам альбома и артиста и открытому меню — на десктопе и на телефоне.
- Тестовая подборка с реальными случаями тегов (кириллица, cp1251, «feat.», сборник, диски, битые теги) прогоняется через сканер вручную. Найденное закреплено тестами бэкенда (`tests/test_tags.py`, `tests/test_library.py`), а E2E-библиотека повторяет главное: гостя через «feat.», сборник и альбом на двух дисках с обложкой над папками CD1/CD2.
- Плеер в E2E играет настоящий звук: Chromium проигрывает сгенерированную библиотеку (Opus-перекодировки, MP3 как есть). Проверяются переключение, перемотка до конца, повтор, конец очереди, очередь после перезагрузки, запись прослушивания и «Недавно слушали», Media Session, мини- и полноэкранный плеер на телефоне, очередь поверх страницы на узком окне; axe — с играющим треком, открытым меню трека, очередью и полноэкранным плеером. «Моё» в E2E: лайки и избранное (и лайк в очереди после перезагрузки), плейлист от создания до удаления с перетаскиванием и проверкой порядка на сервере, история с настоящим прослушиванием и очисткой, телефонная медиатека; axe — на этих страницах и в их диалогах. Поиск в E2E: «/» с главной, результаты по мере ввода, лучшее совпадение и его воспроизведение, один вид результатов и возврат к нему «назад», опечатка, пустой результат, телефон. Тексты: из `.lrc` рядом с треком, из тегов, отсутствие текста, смена трека, текст в полноэкранном плеере; axe — на поиске и текстах. Администрирование в E2E — последним, отдельным проектом (загруженный альбом изменил бы то, что считают тесты каталога): числа медиатеки и скан, загрузка сгенерированной папки альбома с обложкой, `.lrc` и кириллическим именем файла (обложка и текст подхватываются), копии файла из библиотеки и файла, который только называется mp3, ошибка задачи и её очистка, пользователи от создания до удаления со входом под новым паролем; axe — на всех вкладках, в диалогах и меню, на телефоне. Chromium запускается с UTF-8-локалью: без неё он не читает выбранные файлы с нелатинскими именами.
- Связка: Playwright (1.56.1 — под Chromium облачного окружения) против настоящего стека: отдельная схема `thule_e2e`, библиотека из сгенерированных ffmpeg треков, API + воркер + собранный фронт на отдельных портах.
- Контракт: типы фронта генерируются из OpenAPI; проверка падает, если они отстали от бэкенда.
- CI нет: проверки запускаются в облачной сессии и локально; скриншоты новых экранов прикладываются к отчёту.
